\title{Nafs-Aql: A Verifier-Gated Dual-Process Architecture on Small Qwen Models for CPU-Only Deployment}
\author{Dirac~R\&D~Team%
\thanks{Manuscript of November 2026. Contact: Dirac R\&D Team. All measurements were taken on one four-core machine shared with other workloads (Section~\ref{sec:eval}); sample sizes are small and are stated with each result.}}
\markboth{Nafs-Aql: A Verifier-Gated Dual-Process Architecture}{Dirac R\&D Team: Nafs-Aql}
\maketitle

\begin{abstract}
We present \Sys, a dual-process language-model system that runs on four CPU cores with no GPU. A 1.7B Qwen3 model answers at once; a 4B reasoning model is consulted only when a gate, derived from expected loss, judges that the error it is expected to remove is worth the waiting time. Where an answer can be checked (mathematics, code, structured data, Lean proofs) an exact verifier decides, and every reply carries an assurance level. We give a formal model whose results fix the design: the optimal gate is a threshold rule on a calibrated error estimate; the precision of a verified answer is bounded by the verifier's false-accept rate, not by model strength; unverified self-refinement converges to a fixed point that can be worse than the first draft, while a verifier-gated loop has risk linear in the false-accept rate; and plurality voting cannot repair confidently wrong answers. The system is a single Rust gateway with its own inference engine, a verifier-scored agent harness for code, a knowledge base that reads PDF pages by their layout and searches an in-process lexical and vector index with a graph built without a model call, one addressable namespace for documents, memory files, skills and saved chats with summaries made without a model, a rule-based check of each answer against its sources, and two memories that need no model, one of verified answers and one of earlier conversations. On a shared Intel i3-8100, with the verifier visible the gate matched reasoning-only accuracy at 0.36 of its cost; a hybrid search over 847 passages takes 0.15\,s, of which the search itself is 0.2\,ms; 18 of 20 held-out questions were answered from passages against 0 to 2 without; a follow-up question finds its passage first ten times as often when it is read with the turn before it; and reading PDF pages by their layout, with vectors for each passage's sentence windows, puts the answering passage first for 0.875 of quoted questions against 0.768 and 0.386 of two-passage questions against 0.284. We report with equal weight what did not pay, including speculative decoding, 1-bit weights, concurrent hedging and a difficulty signal read from the question alone.
\end{abstract}
