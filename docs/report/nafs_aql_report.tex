\title{Nafs-Aql: A Verifier-Gated Dual-Process Architecture on Small Qwen Models for CPU-Only Deployment}

\begin{abstract}
We present \Sys, a hybrid System~1 / System~2 language-model architecture built from small, openly licensed Qwen models and designed to run on a CPU-only machine. The design borrows its vocabulary, as an explicit analogy, from the classical Islamic account of the self: the impulsive \emph{nafs}, the arbitrating \emph{\textquoteleft aql}, the integrating \emph{qalb}, and the practices of self-accounting (\emph{muhasaba}) and purification (\emph{tazkiya}). We turn this inspiration into a formal model with explicit state spaces, operators, costs and losses, and prove the properties that drive the engineering choices: the gate between the fast and slow paths is a threshold rule on a calibrated error estimate; precision on verifiable tasks is bounded by the verifier's false-accept rate and not by model strength; unverified self-refinement converges to a fixed point that can be worse than the first draft, while a verifier-gated loop has risk linear in the false-accept rate; plurality voting cannot repair confidently wrong tasks; and a Beta-prior optimal-stopping rule yields the retry cap. Each result is mapped to a parameter or an algorithm of the specification. We verify the stack against current documentation: Qwen3 and Qwen3.5 are the only Qwen generations with open weights at or below 9B parameters; vLLM's CPU backend requires Linux and prefers AVX-512; Unsloth requires a GPU for training, so fine-tuning is scheduled on rented GPUs with GGUF export for CPU inference; and a Rust gateway (axum, tokio) fronts both vLLM and llama-server through the OpenAI-compatible API. On the reference machine (Intel i3-8100, AVX2, 32\,GB) we measured 15.5 decoded tokens/s for Qwen3-1.7B in 4-bit, consistent with a memory-bandwidth roofline. We give the architecture, the implementation stack, the evaluation plan with statistically sized gates, and a summary of the companion specification and roadmap. Version~2.0 adds the implemented system and its measurements on a shared four-core CPU. With an exact verifier visible, the gate matched deliberate-only accuracy at about a third of its cost. Stage-level latency attribution shows that System~1 decode speed dominates the fast path, and an early-escalation rule removes the remainder of drafts the gate will reject anyway. A Qwen3.5-2B System~1 was 17 points more accurate but 3.7 times slower, so it was not adopted. These quality results are indicative: sample sizes are far below the release gates. Version~2.1 integrates mechanisms from two open agent harnesses: from Open Math Harness, Lean~4 as an exact verifier under a frozen-statement protocol and a best-first repair tree scored by the verifier, which provably reduces to the previous loop when verdicts are all-or-nothing; from OpenAI's Codex, the \texttt{apply\_patch} format for code repairs and a bounded code agent that stops only when the exact verifier accepts. Version~2.2 rebuilds that agent on the harness mechanisms of Codex's agent core, adapted to small models on a CPU: an append-only transcript that keeps the server's prompt cache valid, compaction written by the harness, Codex's patch grammar as a per-step decoding grammar that leaves the reasoning span free, and a whole-file edit policy for short files. In an interleaved live A/B the new loop verified \HABOneNewVerified{} of \HABOneNewN{} System~1 tasks against \HABOneOldVerified{} for the old one, with malformed steps falling from \HABOneOldMalformed{} of \HABOneOldActions{} to \HABOneNewMalformed{} of \HABOneNewActions{}, and all \HABTwoNewN{} System~2 tasks in one call each, where the old loop verified none in \HABTwoOldCalls{} calls; with a smaller reasoning budget on the first step a verified System~2 fix of a small function took 33--59\,s. Samples are small. Version~2.3 validates the whole system end to end on the final code (190 Rust tests, 26 security probes, 65 API and UI checks, 59 Rooms checks, 40 harness checks, 9 acceptance tests), finds and fixes three defects in the Lean integration, and reports that Qwen3-4B-Thinking cannot yet write valid Lean~4 proofs even for trivial statements, so Lean tasks abstain honestly rather than verify.
\end{abstract}
