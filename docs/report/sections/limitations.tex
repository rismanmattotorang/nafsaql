\section{Limitations}
\label{sec:limits}
\textbf{Indicative results.} Every measurement comes from one shared
four-core machine with tens to a few hundred items per comparison. Verified
counts that differ by one or two tasks are within sampling noise (the same
ten agent tasks verified four and five times in two rounds of the same arm).
A release-scale evaluation needs thousands of paired items and a quiet or
faster host. The formal results hold under their stated assumptions, several
of which (conditional independence of verifiers, a Beta prior on acceptance,
homogeneous refinement dynamics, concave budget returns) are modelling
choices.

\textbf{The calibrated gate is not yet in force.} The ledger holds 1{,}294
labelled drafts of the 2{,}900 its promotion rule asks for, and only one of
five bins is certified at the default bound, so the fixed rule decides. Token confidence is a weak signal for these models on
mathematics; a draft whose samples all repeat the same wrong answer is kept.

\textbf{Verifiers are partial.} Only code, mathematics, structured output and
Lean statements have exact verifiers; everything else is at best a consensus
or judge assurance, which Theorem~\ref{thm:plurality} shows has a floor.
Test-based verification can be gamed by overfitting to visible tests, which is
why tests are hidden and the code verifier's false-accept rate is measured by
mutation. The 4B model does not write valid Lean~4 proofs, so Lean tasks
abstain; Mathlib is not installed.

\textbf{Shared weights.} The fast and slow paths come from one model family
and make correlated errors; the collision term of
Proposition~\ref{prop:collision} is not small a priori, and the judge shares
the bias, which is why exact verifiers carry the safety case.

\textbf{The CPU.} A deliberate answer takes minutes. The default engine's
server lacks grammars, $n$-choice requests and raw continuation, so the
rescue, the cascade and the adaptive exit run at full strength only on the
llama.cpp backend. Engine-flag studies were inconclusive under shared load.
Distillation of the quick model and pre-training of the memory module need a
GPU and were not run.

\textbf{Knowledge.} Questions worded differently from the document are found
in the first eight passages only a quarter of the time. The remedies
(a reranker, a stronger embedder, questions written for each passage at
indexing time) need larger models or hours of the quick model. No public
retrieval benchmark was run, so there is no comparison with published
systems. The model-built graph costs a model call per passage, and community
summaries are not built. The \LaTeX\ reader leaks macro names inside
mathematics. At 50{,}000 passages search by words through the store is slow
under load. The support check compares words and numbers: it flags a sentence
that is not in the passages, and it passes a wrong sentence assembled from
the passages' own words. The rule for follow-up questions reads one previous
turn and is written for English.

\textbf{Memory.} Memory tokens do not work without pre-training, and no
module trained with the corrected recipe exists yet. The memory of earlier
conversations is one person's: outside chat rooms the system has no accounts,
so everyone who can reach an installation shares it. Its gate is a word list,
so a question that needs an earlier conversation without saying so is
answered without it.

\textbf{The agent.} Tasks are single-file functions; there are no subagents,
no plan mode and no byte-exact replay of a prompt from the trace. Grammar
constraints fix the syntax of an action, not its sense.

\textbf{Security and privacy.} The system executes model-written code in a
sandbox and consumes untrusted text; prompt injection through retrieved
passages or tool output is a first-class threat
\cite{greshake2023injection,perez2022ignore}. Retrieved content is delimited
as data, relations enter a prompt only with a verbatim quote, and observed
content never changes controller parameters; classifiers for jailbreaks and
personal data are pattern-based, not trained. Conversation traces feed the
ledger; using them for training requires consent, retention limits and
redaction.

\textbf{Faithfulness.} Separating the reasoning from the answer does not make
the reasoning faithful \cite{turpin2023unfaithful,ji2023hallucination}; the
trace is evidence for debugging, not an explanation to the user. The system
makes no claim of consciousness or moral standing; its name is an analogy
(Section~\ref{sec:intro}).
