\section{Phase 24: Head to Head with vLLM Semantic Router and DeepSeek Harness}
\label{sec:phase24}

Phase~22 read the two projects for \emph{mechanisms}. This phase asks what each costs on the work done on every request, measures it where the same work can be
run on both sides, ranks the gaps and closes the ones that were real (9 November 2026; shared host, load average 24 to 29 on four cores, so every time is a
pessimistic bound for both sides). Records: \texttt{docs/research/semantic\_router\_deepseek\_h2h.md},
\texttt{docs/spec/headtohead\_spec.md} (FR-P1 to FR-P4, NFR-P1) and \texttt{docs/decisions/017-embedder-and-headtohead.md}. No project called ``Semantic Router
Duo'' exists in the sources; the request is read as the pair of projects.

\subsection{What each project is}

Semantic Router (Go, Envoy and Kubernetes) is a decision layer in front of many models: about twenty signal types, Boolean rules over them, a selection algorithm.
It decides correctness by model confidence, self-rating or peer agreement; no exact verifier runs in production. DeepSeek Harness (\texttt{dsh}, TypeScript) is a
ReAct loop over an event-sourced session log whose runs end on the model's own claim. Nafs-Aql is a single Rust gateway for four CPU cores whose answers are
accepted by exact verifiers and whose gate is an expected-loss rule with a certified per-bin error bound. The two others are ahead on breadth: Envoy and Kubernetes
integration, roughly twenty signal types with trained jailbreak and PII classifiers, a dashboard, byte-exact prompt replay, subagents at scale, and browser and
computer-use tools. None of these is affordable per request on this machine, and each is recorded as not adopted rather than as a gap to close.

\subsection{Measured}

The Go benchmarks of Semantic Router that compile offline (\texttt{GOPROXY=off}: lexical keyword signal, prompt compression, vector maths) were run interleaved with
their Rust counterparts (\texttt{rust/crates/nafs-bench/examples/h2h.rs}), five rounds, median (\texttt{benchmarks/headtohead/}). The other upstream packages need
downloads that were not approved, and \texttt{dsh}'s benchmarks need a package install, so its enforced CI budget is quoted instead.

Two results go against a simple ``Rust is faster'' reading. First, their hand-written AVX2 assembly is 1.3 to 1.5 times faster than our intrinsics at $n\ge768$;
the difference is 50 to 60\,ns on a vector search that costs 18 to 22\,ms a query, at most 0.2\,\% of it, and it stays open. Second, the per-request cost of both
signal layers is negligible beside one model call ($10^{5}$ to $10^{7}$ times longer), so what separates the projects is accuracy work (certified bins, exact
verifiers), not these numbers.

\subsection{What was closed}

\begin{itemize}
\item \textbf{The sentence packer} recomputed each sentence's words twice per pass; it now does so once. At 16K tokens the first run took 27.1\,ms and the five-round
  median is 8.96\,ms (different loads; read it as the order of magnitude), which is 2.4 to 5.6 times faster than their \texttt{Compress}.
\item \textbf{The dot product} had only a portable loop (1.9\,\textmu s at $n=1024$); an AVX2 + FMA kernel with eight accumulators, selected once per process, takes
  199\,ns and agrees with the portable one to $10^{-3}$ relative on every tested length.
\item \textbf{An optional exact vector cache} (Section~\ref{sec:phase23}) and the label stream's visibility: the Quality page now shows whether the stream is
  practising and how many of the 2,900 checked answers the learned rule needs are held (424 at the time of the screenshot, 21\,\% wrong).
\end{itemize}

\subsection{A stronger embedder, measured and not adopted}

Qwen3-Embedding-4B (2,560 dimensions) was compared with the 0.6B model on the same 122 passages, 49 quoted and 20 paraphrased questions. Alone, the meaning arm is
better with the larger model (paraphrased R@1 0.25 to 0.45, MRR 0.361 to 0.534; quoted R@1 0.63 to 0.73). In the hybrid that ships it is not: the best pooled MRR over 69
questions is 0.804 for the 0.6B model at weight 0.2 and 0.787 for the 4B model at 0.5, with words alone at 0.909 on quoted questions for both. The larger model costs
about four times the embedding time, 2.5 times the storage and a separate index, so the 0.6B model and weight 0.1 stay (decision 017). Twenty paraphrased
questions cannot separate weights 0.1 and 0.2; the choice rests on the pooled 70.

\subsection{Specified and not built}

Byte-exact replay of a model request from the trace (FR-H6) needs the text that replaced older messages after a prune or compaction, which a step does not yet record;
spill of long results to a file (FR-H5) waits for a read action; the difficulty prior (FR-R5) waits for labels; trained jailbreak and PII classifiers, an Envoy filter and
subagents at scale are not adopted, with the reasons in the specification.
