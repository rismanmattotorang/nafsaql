| A-020 | Calibration promotion (NFR-020, review H1) uses **out-of-fold** predictions: 5-fold cross-validation, isotonic post-correction fitted on other folds, ECE with 5 equal-mass bins, and promotion only when n >= 2,900, each class (draft wrong / right) has >= 30 examples and the held-out ECE <= 0.05. The 10-item calibration produced in Phase 1 was retired to `data/runtime/gate_calibration.legacy-n10.json`. | The spec asks for ">= 2,900 held-out samples"; cross-validation lets every labelled sample serve as held-out once instead of needing about 10,000. | If a fixed hold-out split is required, set `calibration_min_n` to the hold-out size and split before fitting. |
| A-021 | The rubric judge (FR-034) runs on System 2 with a 64-token thinking budget instead of "non-thinking mode at temperature 0": Qwen3-4B-Thinking-2507 has no non-thinking mode, llama-server treats a budget of 0 as unlimited, and a budget of 1 leaks reasoning into the answer (measured). Temperature 0, seed 0. | A-023 | The audit stream (FR-040) re-answers kept requests with System 2 only while no user or evaluation request is in flight, and yields (the audit stays pending) the moment one arrives. | A-024 | The Prop. 3 caps are fitted with a Beta-geometric likelihood over System 2 attempts (first passing attempt, right-censored at the attempt budget). | A-030 | Code-verifier φ is measured with simple textual mutants. Most surviving mutants flip a boundary (`<` and `<=`, `>` and `>=`) and also pass the EvalPlus suites (HumanEval+, MBPP+), which have dozens to hundreds of tests per task. | A-040 | In docker compose the gateway runs with `seccomp=unconfined` and `apparmor=unconfined`, because the verifier creates unprivileged user, network, mount and PID namespaces and mounts inside them (`unshare -rnm`, then `-pf`), which Docker's default seccomp profile forbids (namespaces) and its default AppArmor profile forbids (`mount`). | A-046 | Early escalation (FR-080) uses N = 32 tokens and a margin of 0.04 nats below the fixed rule's mean log-prob threshold, chosen from a 40-prompt study as the setting with the most saved tokens among those with no wrong early escalation. | A-047 | The adaptive reasoning exit (FR-082, P7-T08) probes for an answer at reflection signals ("Wait", "Alternatively", "Hmm", "Let me double-check", ...) with a minimum gap of 64 reasoning tokens, and at the latest every 256 tokens. On verifiable tasks the exact verifier decides whether to stop (the design's own evidence rule, Theorem 1); on factual tasks two consecutive agreeing probes do (Dynasor-CoT). The final answer is always generated after the reasoning exactly as on the standard path, so the exit changes only how much reasoning is generated. It runs on llama-server's raw continuation endpoint with the cached prefix, so each probe costs a few prompt tokens plus at most 24 generated tokens; vLLM uses the standard path. The published methods (DTSR, DEER, Dynasor-CoT) were evaluated on 8B and larger models; the 4B System 2 was measured here with the `slow_noexit` Lab system: on 12 GSM8K items (11 scored in both arms) accuracy was 100% with and without the exit, mean wall time fell from 220 s to 123 s (−44%; median 222 s to 91 s) and mean reasoning tokens from 723 to 348 (−52%); the p95 barely moved (331 → 323 s), because some items use the whole budget either way, and one item exceeded the wall-clock cap in both arms. | The deliberate path is 97% System 2 reasoning on this CPU, and the literature reports 29–35% fewer reasoning tokens from such exits. | A probe that passes the verifier on a lucky partial answer stops reasoning early; the final answer is verified again, so correctness is unaffected, only the trace is shorter. A wrong early stop on factual tasks costs accuracy, which the paired Lab comparison measures. |
| A-048 | EAGLE-3 speculative decoding was measured for both systems (AngelSlim heads, Q8_0) in interleaved A/Bs on the reference CPU. System 1 (Qwen3-1.7B): 1.04x decode speed at temperature 0 and 0.95x at the production temperature with 4 draft tokens (acceptance 49–52%), 0.86–0.93x with 8 (`benchmarks/eagle3_ab_system1.json`). System 2 (Qwen3-4B-Thinking, reasoning prompts): 0.99x with 4 (acceptance 46%), 0.87–0.91x with 8 (`benchmarks/eagle3_ab_system2.json`). On four cores the verification pass of several draft tokens costs real compute, so at this acceptance rate it does not pay; math prompts alone gained about 20% on System 1 and open-ended ones lost more. FR-081 is not met for either system, so the head stays opt-in (`EAGLE=1 scripts/serve_llama.sh start`). The A/B's "greedy identical" share (15%) is not evidence about the head: the plain server itself returned different greedy outputs in 1 of 3 repeats under load (multi-threaded reductions are not bit-reproducible), so identity is judged by acceptance statistics and the speed-up only. | The GPU figures (1.69x) assume verification of a draft is nearly free, which holds on a GPU and not on a 4-core CPU. | A faster CPU with more cores, or a head trained on this deployment's traffic, could change the verdict; the A/B script re-measures it in minutes. |
| A-049 | Under the fixed rule the k cheap samples are drawn sequentially after the draft and only when the draft's mean log-prob lies within 0.10 nats of the threshold (`gate.samples_when_uncertain`, `gate.uncertain_band`); confident drafts skip them, and samples requested on verifiable traffic for calibration data are still always drawn. | A-053 | `isolation_available()` is a functional probe on Linux, not a check that the `unshare` binary exists: it runs the whole isolation stack (all stages, see A-054) around a small script that asserts the sandbox is in force (scratch writable, `/etc` not writable, `fork` denied), once per process.
